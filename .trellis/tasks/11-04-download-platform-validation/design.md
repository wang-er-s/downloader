# 平台集成验收设计

## 依赖与证据

依赖前六个子任务可集成及各自测试记录。沿用[设计平台矩阵](../../../.agents/specs/download-manager/design.md)，本任务不增设新产品要求。使用任务目录内的 acceptance.md 和 evidence/ 记录实施时真实结果；当前不创建虚假 pass 或占位证据。

每条需求记录源 ID、实施子任务、实际测试与环境、证据路径、结果和剩余问题。平台不可用记 unverified；源码证据、fake 测试、原生编译、真实运行和实体设备结果分开记，不能相互替代。

## 核心验证

受控 HTTP 服务记录请求/Range/ETag，检查重启和恢复是否引入未批准的传输。故障注入在原生日志、AppStore 事务、确认和发布阶段分别中断；核对次数、文件散列、身份和持久状态。

文件测试覆盖每个平台默认位置、持久授权目录、未知提供方和取消/删除；UI 端到端覆盖 49 项中的所有操作与反馈。数据规模采用设计初始样本：100 条历史记录、两个活动任务和超过 4GiB 的可控大文件。

## 构建与交付边界

Android、macOS、Windows 必需；Windows 在真实 Windows 环境构建/运行。iOS 的后台与续传结论必须实体设备，--no-codesign 只证明编译。最终最低系统版本以批准的基线和验证为准，若需提高先报告。

release 构建与分发签名分开，不自动发布商店、上传或推送代码。打包检查插件补丁和 SQLite 原生资产，检查 macOS release 权限不只看 debug。

## 失败处理

集成缺陷回到实际拥有该代码的子任务修复并复测；不能以降 target、删除记录、伪造结果或临时屏蔽测试过关。保留未验收状态及现场，父任务仅在全部必需结果成立时完成。
