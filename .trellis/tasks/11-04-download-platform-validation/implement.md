# 集成验收计划

## 前置

前六个子任务可集成且各自门槛有真实证据后激活。每个平台都需实际环境；没有设备不篡改验收条件，记录阻断并报告。

- [ ] 将源需求的 49 项逐条建 acceptance.md，关联真实测试和所属子任务，不写预置 pass。
- [ ] flutter analyze、flutter test；运行各子任务原生/集成和回归测试。
- [ ] 在实际目标环境执行 flutter build apk --release、flutter build macos --release、flutter build windows --release；iOS 先编译再使用具备签名的实体设备测试，记录具体命令。
- [ ] 核对插件固定补丁、SQLite 原生资产、权限/签名及最低支持版本；本地构建与分发可用性分开记录。
- [ ] 执行五项审查问题故障注入、平台生命周期/目录/文件及 UI 全流程矩阵，收集请求日志和文件/状态证据。
- [ ] 按测试失败归属回修代码、补规范并定向复测；未测保持 unverified。
- [ ] 汇总必需平台结果、iOS 可行性及剩余限制，完成父任务交叉验收后才建议归档。

## 验证断言

Android/桌面终止后无自动请求；iOS 不重复提交；失败/暂停材料保留；未知总长中途字节真实；旧命令/ack 不污染新执行；中断发布不重复目标/覆盖外来文件；取消清理失败保留记录；主题/缓存/目录重开一致。

## 停点与回滚

实际 Windows、iOS 设备/签名缺失时明确报告，不把其他平台通过折算。发现数据或文件安全问题先停扩大验证并保留现场，只回退本任务拥有的测试/配置变更；不自动发布、提交或清理用户文件。
